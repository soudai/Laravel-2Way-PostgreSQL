    PostgreSQL固有機能

    型付き配列、JSON文書、期間型、MERGE、OLD/NEWとPostgreSQL 19の機能。

    バージョン別の使い分け

    現在の対象はPostgreSQL 18/19です。19はRC1で先行検証したもので、正式版の検証完了とは区別しています。

    機能 必要な宣言・条件
    MERGE、OLD/NEW RETURNING 18/19、適切なwrite / write_returning
    配列・JSONB・range・multirange 18/19、型を明示。型付き結果はCodec登録
    ON CONFLICT DO SELECT postgres_min_version=19、主文INSERT＋RETURNING、write_returning
    plan advice postgres_min_version=19、DB側module準備、明示ID選択
    JSONPath upper()、19追加range関数等 postgres_min_version=19。18への自動代替なし
    php
    'postgres_min_version' => 19,

    宣言不足は対応する検査で TW_COMPATIBILITY、18の接続への19専用実行は TW_CONNECTION になります。DDL・extensionの導入はアプリのmigrationやDB運用で行います。

    標準Codecの登録

    アプリのServiceProviderのbootで一度登録します。

    php
    use Hft\TwoWaySql\Parameter\Registry\CodecRegistry;
use Hft\TwoWaySql\Types\PostgresTypes;

public function boot(): void
{
    PostgresTypes::register($this->app->make(CodecRegistry::class));
}

    queries.<ID>.parameters と codegen.results.<ID> に同じ codec:ID を宣言すると、入力・結果DTO・生成コード・PHPStanで型を共有できます。DTOの対象引数には #[Hft\TwoWaySql\Attributes\SqlType('ID')] を使用します。生成DTOでは属性も自動で付きます。

    型付き配列

    Codec ID PHP要素型 SQL cast
    pg.array.int64 int bigint[]
    pg.array.text string text[]
    pg.array.uuid UUID文字列 uuid[]
    pg.array.bool bool boolean[]
    pg.array.decimal 十進文字列 numeric[]

    NULL要素を許可するIDは .nullable_elements を追加します。列のSQL NULLは、さらに利用箇所のnullable=trueで宣言します。

    php
    'flags' => ['type' => 'codec:pg.array.bool.nullable_elements', 'nullable' => true],
    sql
    SELECT /*:flags*/'{true,NULL}'::boolean[] AS flags

    SQL NULL / {} / {NULL} / {"NULL"} は、順にPHP null / [] / [null] / ['NULL']です。配列全体を1bindにし、INのリスト展開とは区別します。一次元・下限添字1だけを受け付け、多次元や下限0は TW_MAPPING。標準上限は8 MiB / 10000要素です。

    JSON文書の精度

    codec:pg.jsonb.document は JsonDocument を入出力に使用します。JSON数値をPHPのfloatへ変換せず、object/array/nullの構造を保ちます。

    php
    use Hft\TwoWaySql\Types\JsonDocument;

$document = JsonDocument::fromJson('{"amount":12345678901234567890.123456789}');
// 入力宣言: value => ['type' => 'codec:pg.jsonb.document']
$parameters = ['value' => $document];
    sql
    SELECT /*:value*/'{}'::jsonb AS value

    JSON nullは JsonDocument::fromJson('null')、SQL NULLはnullable宣言とPHP nullです。kind() はobject/array/string/number/boolean/nullを返し、raw() で検証済みJSONを明示取得します。既定8 MiB・深さ64。JSONBによるキー順・空白・重複キーの正規化は維持されるため、原文byte列の再現ではありません。

    range / multirange

    php
    use Hft\TwoWaySql\Parameter\Range\DateRange;
use Hft\TwoWaySql\Parameter\Range\DateMultirange;

$range = DateRange::between('2026-01-01', '2026-01-10');
$available = DateMultirange::of([$range]);
$booked = DateMultirange::of([DateRange::between('2026-01-03', '2026-01-05')]);

    単一区間は組込みのdaterange/tstzrange、複数区間は登録した codec:pg.datemultirange / codec:pg.tstzmultirange を宣言します。SQLのcastは明示します。

    sql
    SELECT /*:available*/'{[2026-01-01,2026-01-10)}'::datemultirange
     - /*:booked*/'{[2026-01-03,2026-01-05)}'::datemultirange AS value

    SQL NULL、空multirange of([])、空range DateRange::empty()、無限端点のnullは別物です。PostgreSQLは区間を整列・統合し、空rangeを除去します。結果の再入力で集合の意味を保ちますが、元の順序・区間数は復元しません。

    TstzRange/TstzMultirangeは時刻の瞬間とmicrosecondsを保持します。表示offsetはDB timezoneで変わる場合があります。multirangeの標準上限は8 MiB / 10000区間。19の range_minus_multi 等は複数行や0行になり得るため、scalar前提にせずselect等で扱います。

    MERGEと変更件数

    MERGEはRETURNINGなしをwrite、ありをwrite_returningで登録します。ループからsourceのVALUESを作ることもできます。

    sql
    MERGE INTO items AS target
USING (VALUES (/*:id*/1::bigint, /*:value*/'sample'::text)) AS source(id, value)
ON target.id = source.id
WHEN MATCHED THEN UPDATE SET value = source.value
WHEN NOT MATCHED THEN INSERT (id, value) VALUES (source.id, source.value)

    上例はid:int64・value:text、kind=writeで登録します。execute / executeExpecting / batchの件数はPDOのMERGE command tagを使い、入力数から推測しません。DO NOTHINGは変更しません。BY SOURCEのDELETEを使う同期ではテナント等の対象範囲もSQLに明示してください。

    action別の結果が必要なら RETURNING merge_action() AS action, old.id AS old_id, new.id AS new_id を付け、kindをwrite_returningにします。INSERTのold・DELETEのnewはNULLです。

    OLD/NEW RETURNING

    sql
    UPDATE items SET value = /*:value*/'sample', version = version + 1
WHERE id = /*:id*/1
RETURNING WITH (OLD AS previous, NEW AS current)
    previous.value AS old_value, current.value AS new_value,
    previous.version AS old_version, current.version AS new_version

    id:int64・value:text、kind=write_returningとして登録します。更新前後の列aliasを明示し、returningAsのDTOへ対応させます。列重複や変換失敗は TW_MAPPING となり、当該更新scopeをrollbackします。

    PostgreSQL 19のget-or-create

    sql
    INSERT INTO get_create_items AS target (id, value)
VALUES (/*:id*/1, /*:value*/'sample')
ON CONFLICT (id) DO SELECT
RETURNING id, value, version, old.id AS old_id

    テーブルはid bigint PRIMARY KEY、value text、version int NOT NULL DEFAULT 0を事前に作成します。kind=write_returning・postgres_min_version=19、入力id:int64・value:text。既存行のvalueを上書きせず、既存行か新規行を返します。

    返却行数・command tag件数・実変更数は異なるため、returning / returningAs専用です。execute / executeExpecting / batchは使用しません。条件付きDO SELECTでは0行になり得ます。INSERT側triggerやsequenceの実行可能性、競合待機、必要なrow lockはアプリ側で考慮します。

    PostgreSQL 19のplan advice

    DB側でpg_plan_adviceをロードし、対象SQLをpostgres_min_version=19と宣言します。configのplan_adviceには信頼済みID、SQL ID、レビューしたquery hash、adviceを固定します。

    php
    'plan_advice' => [
    'users.scan.v1' => [
        'query_id' => 'users.search',
        'query_hash' => '<レビューしたcompile結果の64桁SHA256に置換>',
        'advice' => 'SEQ_SCAN(u)',
    ],
],

    hashは合成入力の compile(...)->hash またはexplainのquery_hashで取得します。この例のplaceholderは実際の64桁hashへ置換してください。入力からadviceや登録hashを組み立てず、SQLと一緒にレビューします。

    ExecutionOptions(planAdviceId: 'users.scan.v1') またはexplainの --advice=users.scan.v1 で明示選択します。SQLの分岐・IN要素数・定義が変わりhashが違えば拒否します。1つのIDを別クエリやpaginateのCOUNT/dataへ流用しません。

    適用中はtransaction/savepoint内で設定し、終了時に戻します。feedbackのmatchedは高速化の保証ではありません。条件式や生のadviceは診断へ出さず、固定の適合フラグで確認します。自動最適化・永続advice・pg_hint_plan互換は提供しません。

    独自型を共有する

    入力Codecと結果ColumnConverterを実装し、registerType(new TypeDescriptor(id, inputType, resultType, postgresType, nullable: ...), inputCodec, resultConverter) で登録します。

    同じIDを入力/結果の codec:ID とDTOのSqlTypeに指定すると、生成・PHPStanでも共有できます。descriptorと利用箇所の両方でNULLを許可する必要があります。NULL時はconverterを呼びません。変換の意味を変える場合はIDを更新し、生成物も再生成してください。
