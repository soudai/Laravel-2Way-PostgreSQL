    パラメータと型

    必須キー・NULL・型の契約と、入力DTO・Codecの選び方。

    入力は宣言済みのキーだけ

    queries.<SQL ID>.parameters に型を宣言し、呼び出し時は連想配列か SqlParameters 実装を渡します。宣言したキーはnullableでも必須です。余分なキー、型違い、必須キーの欠落はSQL実行前に拒否します。

    php
    // 宣言
'filter.name' => ['type' => 'text', 'nullable' => true, 'max_bytes' => 200],
// 入力
['filter' => ['name' => null]]

    dot pathはネストした配列で渡します。['filter.name'=>null] や ['filter'=>[]] は無効です。非選択の分岐でも同じ検証を行います。例外は patch<record> の内部フィールドで、省略を「更新しない」として扱います。

    組込み型

    type PHPで渡す値 注意点
    int64 int 数値文字列・floatの暗黙変換なし。min/maxを設定可能
    text string UTF-8、NUL不可。max_bytesで制限
    bool bool 0/1や文字列ではなくtrue/false
    uuid UUID文字列 形式を検査
    decimal 十進文字列 floatへ変換しない
    jsonb JSONとして扱うPHP値、JsonValue SQL NULLとJSON nullを区別
    date 日付文字列 例: 2026-01-01
    timestamp timezoneなしの日時文字列 YYYY-MM-DD HH:MM:SS.ffffff。6桁の小数部が必須
    timestamptz DateTimeInterface 明示した時刻の瞬間・microsecondsを保持
    list<int64> / list<text> / list<uuid> list配列 IN/NOT INで要素数分のbindを生成
    pg_array<int64/text/uuid/bool/decimal> 対応型のlist配列 型名の / は選択肢。実際はpg_array<int64>等を指定
    list<record> 連想配列のlist fieldsを宣言し、ループで利用
    patch<record> 更新するfieldだけの連想配列 fields・columnを宣言。rootはNULL不可
    daterange / tstzrange DateRange / TstzRange 空range・無限端点・SQL NULLを区別
    codec:ID 登録Codecの入力型 信頼済みProviderで事前登録

    スキーマオプション

    キー 適用先 既定 / 意味
    type 全て 必須。型名
    nullable 全て（patch rootは不可） false。PHP nullをSQL NULLとして許可
    min / max int64 指定なし。整数の範囲制約
    max_bytes text 個別指定なし。0以上のbyte数。全体のlimitsは別に適用
    elements_nullable pg_array false。配列中のNULL要素を許可
    fields list<record> / patch<record> 必須。非空のフィールド定義
    column / protected patchの各field 更新列名は必須。保護の既定は列名・field名による

    未知のオプションや、その型に適用できないオプションはエラーになります。

    INリストとPostgreSQL配列

    sql
    -- list<int64>: [1, 2] は2個のbind。空配列の展開はエラー
SELECT id FROM users WHERE id IN /*:ids*/(1, 2)
    sql
    -- pg_array<int64>: 配列全体を1個のbind。空配列も利用可能
SELECT id FROM users WHERE id = ANY(/*:ids*/'{1,2}'::bigint[])

    同じPHP配列でも宣言型によって意味が変わります。SQL NULLの配列、空配列、NULL要素だけの配列を混同しないでください。配列の結果も型付きで扱う場合は 標準PostgreSQL Codec を使用します。

    JSONと精度

    nullableなjsonbにPHP nullを渡すとSQL NULL。JSON nullは明示的に Hft\TwoWaySql\Parameter\JsonValue::null() を使います。PHP値としての数値精度を保持できない場合は、最初から十進数の原文を保つ JsonDocument を選んでください。

    LIKE検索

    php
    use Hft\TwoWaySql\Parameter\LikePattern;

$parameters = ['pattern' => LikePattern::contains('20%_off')];
    sql
    SELECT id FROM users WHERE name LIKE /*:pattern*/'%demo%' ESCAPE '!'

    patternはtextとして宣言します。contains / startsWith / endsWithが %、_、! をエスケープします。SQL側の ESCAPE '!' と組み合わせて使用してください。

    入力DTO

    php
    <?php
namespace App\Queries;

use Hft\TwoWaySql\Contracts\SqlParameters;

final readonly class SearchParams implements SqlParameters
{
    public function __construct(public int $tenantId, public ?string $name) {}

    public function toSqlParameters(): array
    {
        return ['tenantId' => $this->tenantId, 'name' => $this->name];
    }
}

    Manager/Executorはこの明示変換を呼び、戻り値を通常のスキーマで検証します。任意オブジェクトのgetter・magic propertyを自動探索しません。DAO生成で使う入力DTOには codegen.parameters の対応宣言も必要です。

    拡張Codec

    ServiceProviderのbootで CodecRegistry::register(id, ParameterCodec) を使うと入力用Codecを追加できます。入力と結果を同じ型で扱う場合は registerType(TypeDescriptor, ParameterCodec, ColumnConverter) を使います。

    Codec IDは小文字で始まる英数字・_.-、1〜64文字、最大256登録。同じIDを上書きできません。SQLの型castはSQL側に固定し、IDからSQL断片を生成しません。Codecは値や接続を共有状態に保持せず、副作用のない決定的な変換にしてください。

    型の共有、標準配列、JSON文書、multirangeの例は PostgreSQL機能 を参照してください。
