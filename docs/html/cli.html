    Artisan CLIリファレンス

    全9コマンドの引数・オプション・DB接続要否・終了コード。

    コマンドの全体像

    Laravelアプリでは php artisan から呼び出します。開発リポジトリにartisanはなく、Testbenchホストで検証するときは vendor/bin/testbench を使用します。以下のオプションはパッケージ固有のもので、Laravel共通の --help 等は省略しています。

    コマンド 役割 DB接続
    twoway:lint 登録SQL全件の構文・宣言を検査 なし
    twoway:cache 検査してASTを温める なし
    twoway:clear 設定したASTキャッシュを削除 なし
    twoway:check 合成ケースの期待値検証 --execute時のみ
    twoway:coverage SQL分岐の通過・未通過を表示 --execute時のみ
    twoway:generate DAOとmanifestを生成・比較 なし
    twoway:generate-schema Params/DTO雛形を生成・比較 なし
    twoway:inspect 結果列metadata候補と差分 隔離DB必須
    twoway:explain 値を除いた推定計画を表示 隔離DB必須

    lint / cache / clear

    bash
    php artisan twoway:lint
php artisan twoway:cache
php artisan twoway:clear

    固有の引数・オプションはありません。lint/cacheは成功0、検査失敗1。clearは正常完了0です。canonicalモードの /* id */ のようなコメントにはlegacy-like警告が出ますが、値のバインドにはなりません。

    check / coverage

    bash
    php artisan twoway:check tests/sql/cases.json --json
php artisan twoway:coverage tests/sql/cases.json --json
php artisan twoway:check tests/sql/cases.json --execute --connection=twoway_test --json
    引数・オプション 既定 説明
    cases 必須 バージョン付きJSONケースファイル
    --execute 無効 検証済み使い捨てDBで実行
    --connection= 指定なし execute時に必須のテスト接続名
    --json 無効 値を含まないJSONレポート

    既定はcompile-onlyです。SQL・bindings・分岐期待を検査し、DB行・更新件数・execute段階の例外期待は照合しません。終了0は指定した段階の成功、1は不一致、2は入力・安全設定の不備です。

    coverageは未通過の分岐も一覧にします。PHPコードcoverageや入力全組合せの網羅性とは別です。ファイル上限は4 MiB、1000ケース、JSON深さ64。v1/v2の使い方は ケースの作成 を参照してください。

    generate

    bash
    php artisan twoway:generate --dry-run
php artisan twoway:generate --write
php artisan twoway:generate --check
    オプション 意味
    --dry-run 差分を表示。省略時の既定動作
    --write 検証した生成物を書き込む
    --check 書かずに鮮度を検査し、差分があれば失敗

    3つのmodeは併用できません。dry-run/writeは成功0、不正2。dry-runは差分があっても0です。checkは一致0、差分1、不正・対象0件等は2になります。

    generate-schema

    bash
    php artisan twoway:generate-schema users.search --params=SearchParams --dto=UserRow --write
    引数・オプション 意味
    query 必須。登録SQL ID
    --params= 入力クラスの短名
    --dto= 結果クラスの短名
    --dry-run 差分表示。既定
    --write 検証済み雛形を書き込む
    --check 選択した雛形の鮮度を検査

    params/dtoの少なくとも一方が必要です。modeの排他制約と終了コードはgenerateと同じです。他query/classの鮮度は確認しないので、CIで必要な対象を列挙します。

    inspect

    bash
    php artisan twoway:inspect tests/sql/cases.json --case=search --connection=twoway_test --against=UserRow
php artisan twoway:inspect tests/sql/cases.json --connection=twoway_test --check --plan=tests/sql/inspection.json
    引数・オプション 意味
    cases 必須。合成入力を提供するJSONケース
    --case= 通常modeで複数ケースがある場合は必須。単一ケースでは省略可
    --connection= 必須。検証済みテスト接続
    --against= 既存の生成DTO短名。通常modeでは任意
    --check metadataの差分・検証不能をCIで失敗扱い
    --plan= check用の全case IDとDTO/除外理由の対応JSON

    checkではcase指定を併用せず、againstまたはplanで比較先を示します。全ケースにDTOか明示除外理由が必要です。planの例:

    json
    {
  "schema_version": "1.0",
  "cases": {"search": "UserRow"},
  "exclusions": {"invalid_input": "入力エラーはtwoway:checkで検証"}
}

    通常modeは候補取得成功0（差分があっても0）、不備・実行失敗2。checkは一致0、差分1、不備・検証不能2です。出力はJSON。列alias・型候補・hash等を含み、結果行は含みません。NULL許容は常に不明です。

    SQLを実行してmetadataを取得します。LIMIT 0を自動付加しません。最大1000列。期待値照合はしないのでcheckを別途実行してください。readの合成ケースを使い、v2のprepare/assertions付きケースは渡せません。

    explain

    bash
    php artisan twoway:explain tests/sql/cases.json --case=search --connection=twoway_test --timeout-ms=2000
    引数・オプション 既定 / 意味
    cases 必須。合成JSONケース
    --case= 複数ケースなら必須。単一なら省略可
    --connection= 必須。検証済みテスト接続
    --timeout-ms= 1000。1〜60000msの計画時間上限
    --advice= 未指定。登録済みplan advice ID、PG19専用

    終了0は診断生成成功、2は設定不備・対象拒否・実行/JSONエラーです。EXPLAIN ANALYZEは提供しません。write、書込みCTE、SELECT INTO、locking、v2のfixture付きケースは拒否します。

    nodeType、cost、planRows、planWidth、children等だけを出し、SQL・条件式・table/index名・入力値は除きます。raw planは1 MiB、深さ32、256 nodes、出力64 KiBまで。costは実測ミリ秒ではなく、性能保証には使えません。計画時の関数評価等もあり得るので、隔離DBで実行します。
