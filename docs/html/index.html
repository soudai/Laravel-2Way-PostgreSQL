    概要・機能一覧

    SQLファイルを中心に、LaravelとPostgreSQLをつなぐための利用ガイド。

    SQL-FIRST · LARAVEL · POSTGRESQL

    SQLを、そのまま
    アプリケーションへ。

    DBクライアントではサンプル値で実行し、Laravelでは同じSQLファイルに入力をバインド。複雑な検索・集計・更新を、SQLとして管理できます。

    最初のクエリを実行する →
    01 / resources/sqlSQLテンプレート02 / config/twoway-sql.php入力型と実行種別を宣言03 / TwoWaySqlバインドしてLaravel接続で実行

    このパッケージでできること

    目的 機能 読むページ
    SQLファイルをアプリで再利用 値・INリストのバインド、条件分岐、WHERE/HAVING/SET補正 SQLテンプレート
    入力を宣言どおりに扱う 型・NULL・余剰キー検証、日時・JSON・配列・range パラメータと型
    取得・更新の契約を明示 厳密な件数、RETURNING、DTO、期待更新件数、バッチ 実行API
    大量データを扱う 明示COUNTページング、カーソルによる逐次取得 ページング・逐次取得
    入力から選べるSQL構造を限定 登録ソート、列選択、部分更新 構造の選択
    型付きの呼び出し口を作る Attributes DAO、Params/DTO生成、PHPStan拡張 コード生成
    デプロイ前に確認 lint、生成物の差分、ケース検証、分岐coverage、結果metadata CLIリファレンス
    PostgreSQL固有の表現を使う MERGE、OLD/NEW、配列・JSONB・multirange、19のplan advice PostgreSQL機能

    対応環境

    項目 条件
    PHP 8.4 / 8.5、64bit、pdo_pgsql・mbstring拡張
    Laravel / Illuminate 12.x / 13.x
    PostgreSQL 18 / 19。19はRC1で先行検証済み、正式版の検証は未完了
    接続 Laravel管理のpgsql接続、native prepares、PDO例外モード
    文字・セッション UTF8、standard_conforming_strings=on

    現行コードの対象はPostgreSQL 18以降で、17には接続しません。19専用SQLにはクエリ単位のバージョン宣言が必要です。確認したリリースと接続先の選び方は対応環境と接続選択にまとめています。

    読み進め方

    01 / STARTまず1つ動かす

    Composer導入、接続設定、SQL登録、実行まで。

     02 / BUILD業務SQLを書く

    条件分岐、ループ、型、取得・更新API。

     03 / REFERENCE設定を調べる

    全設定項目、既定値、実行オプション、上限。

     04 / OPERATE検証して運用する

    ケース検証、キャッシュ、診断、デプロイ。

    アプリケーションが決めること

    Eloquentと併用できますが、Global Scope、認可、テナント条件、SoftDeletes、取得件数制限は自動適用されません。SQLに明記してください。任意のユーザー投稿SQLを実行するための機能ではありません。

    SQLからの完全な型推論、COUNT SQLの自動生成、書き込みの自動再試行、他DB対応、Domaの完全互換は提供しません。静的SQL断片のinclude・COPY・WAIT FOR LSNの公開APIも提供していません。

    このHTMLの使い方

    このフォルダをそのまま取得し、index.html をブラウザで開いてください。ネットワークやビルドは不要です。左の検索で本文・API名・設定キーを探せます。JavaScriptを無効にしても本文とページ移動は利用できます。印刷時は本文中心のレイアウトになります。
