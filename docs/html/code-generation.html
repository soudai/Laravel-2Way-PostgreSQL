    DAO・Params・DTO生成

    SQLの宣言を型付きコードへ。生成物の鮮度とPHPStanの検査を組み込む。

    生成の流れ

    SQLと入力・結果スキーマを宣言し、Params/DTOとDAOをビルド時に生成します。通常リクエスト中にコード生成やDAOのreflection dispatchは行いません。DBへ接続せず生成できます。

    DAO interfaceと結果DTO

    次の例では、users.search をread、入力をtenantId:int64・name:nullable text、返却列をid・nameとします。

    php
    <?php
namespace App\Queries;

use App\Data\UserRow;
use Hft\TwoWaySql\Attributes\SqlQuery;

interface UserQueries
{
    /** @return list<UserRow> */
    #[SqlQuery('users.search', result: UserRow::class)]
    public function search(int $tenantId, ?string $name): array;
}
    php
    <?php
namespace App\Data;

final readonly class UserRow
{
    public function __construct(public int $id, public string $name) {}
}

    SqlQuery のmodeは既定select。select / one / oneOrNull / scalar / execute / returningを指定できます。kindや返却型は 実行API と一致させます。scalar/executeには結果DTOを指定しません。

    php
    'codegen' => [
    'root' => 'app/Generated/TwoWaySql',
    'namespace' => 'App\\Generated\\TwoWaySql',
    'daos' => [\App\Queries\UserQueries::class],
    'parameters' => [],
    'results' => ['users.search' => [
        'id' => ['type' => 'int'],
        'name' => ['type' => 'string'],
    ]],
    'connections' => [\App\Queries\UserQueries::class => 'pgsql'],
],

    named scalar引数はmanifest名・型・NULL許容を一致させます。dot path、list、日時等は1個の非nullable SqlParameters 実装で受け取り、そのクラスの入力スキーマをcodegen.parametersへ登録します。DTOのメソッドをビルド時に実行して型を推測しません。

    optional/default引数、variadic、参照、static、magic method、union/intersection型は対象外です。全public instance methodにSqlQuery属性が必要です。

    生成とDI

    bash
    php artisan twoway:generate --dry-run
php artisan twoway:generate --write
composer dump-autoload

    既定はdry-run。interface短名にImplを付けたPHPとmanifest.jsonを生成します。Providerがmanifestを検査してinterfaceをcontainerへ登録します。

    php
    $dao = app(\App\Queries\UserQueries::class);
$rows = $dao->search(10, null);

    生成先のnamespaceとアプリのPSR-4設定を合わせてください。SQL・config・interface・生成PHP・manifestを同じデプロイで配布します。

    Params / DTO雛形

    bash
    php artisan twoway:generate-schema users.search --params=UserSearchParams --dto=UserView
php artisan twoway:generate-schema users.search --params=UserSearchParams --dto=UserView --write

    生成先はcodegen.rootの Schema/、namespaceも Schema 配下。params/dtoの少なくとも一方を指定します。引数は短いclass名です。DTO生成にはcodegen.resultsの結果宣言が必要です。

    生成ParamsはSqlParametersを実装します。DAOへ渡すときは生成クラスと入力宣言をcodegen.parametersにも登録します。手編集するクラスは生成先の外へ置いてください。

    差分検査と手編集の保護

    bash
    php artisan twoway:generate --check
php artisan twoway:generate-schema users.search --params=UserSearchParams --dto=UserView --check

    checkはファイル・directory・lockを書きません。一致0、欠落・古い生成物・手編集・obsoleteは1、不正宣言や検証不能は2です。generate-schemaは選択したquery/classのみ検査するので、CIでは対象を全て列挙します。

    writeは未管理ファイルや手編集した生成物を上書きしません。設定から外した古いDAOは、以前のmanifestに登録された未編集ファイルだけを削除します。生成ファイルの所有者・読み取り権限をアプリの実行ユーザーに合わせてデプロイしてください。

    PHPStan

    アプリ側でPHPStan 2.1.3以降の2.xを導入し、生成したmanifestとSQLルートを設定します。PHPStanは任意依存ですが、2.1.3未満はComposer conflictの対象です。

    bash
    composer require --dev 'phpstan/phpstan:^2.1.3'
    neon
    includes:
    - vendor/soudai/laravel-2way-postgresql/extension.neon
parameters:
    level: max
    paths:
        - app/Queries
        - app/Data
        - app/Generated
    twowaySql:
        manifests:
            - %currentWorkingDirectory%/app/Generated/TwoWaySql/manifest.json
        sqlRoot: %currentWorkingDirectory%/resources/sql

    雛形も生成している場合は app/Generated/TwoWaySql/Schema/manifest.json をmanifestsへ追加します。

    診断 内容
    twoway.unknownQuery / dynamicQuery 未登録ID、literalとして確定できないID
    twoway.staleSql 生成後にSQLの内容が変わった
    twoway.queryKind 呼び出しAPIとkindの不一致
    twoway.parameterMissing / parameterExtra / parameterType 入力shape・必須キー・型の不一致
    twoway.resultType 結果宣言とDTOの不一致
    twoway.daoSignature / daoAttribute DAO signature・属性・返却型の不一致

    解析自体にLaravelのbootやDB接続は不要です。SQLの完全な型推論ではなく、実DBのNULL・件数・値の形式・動的分岐の結果はruntimeで検証します。独自mapperの意味やpaginateの組合せ等は解析対象外です。

    実DBの列metadataを比較

    twoway:inspect は隔離DBでSQLを実行して列alias/native typeの候補を取得します。nullableはunknownで、宣言へ自動反映しません。通常inspectは差分があっても終了0。CIでは --check --against=DTO短名 または --check --plan=比較計画.json を使います。

    入力ファイル、全オプションと終了コードは CLIリファレンス にまとめています。
