    SQLテンプレート

    バインド、条件分岐、ループ、登録ソート、列選択と部分更新。

    基本ルール

    SQLはUTF-8のファイルで管理します。値の入口は /*:path*/sample、制御命令は /*%...*/ です。制御命令は1行に単独で記述し、値バインドはSQL行内に置けます。大文字・小文字は命令名で区別します。

    構文 用途
    /*:path*/sample 値・リストのバインド
    /*%if 式*/ / /*%elseif 式*/ / /*%else*/ 条件分岐
    /*%where*/ / /*%having*/ / /*%set*/ 句の先頭区切り・空句を整理
    /*%for row in rows separator=", " empty="error"*/ コレクションの反復
    /*%orderBy sort*/ 登録済みソートを選択
    /*%columns projection*/ 登録済み列リストを選択
    /*%assignments patch*/ 宣言済みフィールドだけを部分更新
    /*%end*/ 最も内側の制御ブロックを終了

    SQLは1ファイルにつき1文です。末尾のセミコロンは省略可能ですが、複数文、DDL、COPY、DO、トランザクション制御は実行APIの対象外です。

    値とINリスト

    sql
    SELECT id, name FROM users
WHERE tenant_id = /*:tenantId*/1
  AND id IN /*:ids*/(1, 2)
  AND created_at >= /*:since*/'2026-01-01'::date

    上例の入力宣言は tenantId: int64、ids: list<int64>、since: date。ids=[3,5] は2個のプレースホルダーになります。空リストを実際に展開すると TW_EMPTY_LIST です。

    サンプルは文字列、数値、TRUE/FALSE/NULL等のリテラルです。関数や任意式は置けません。型castはサンプルの後ろへ書きます。/*:since*/DATE '2026-01-01' は無効です。サンプルは入力欠落時の既定値にはなりません。

    条件付き検索とWHERE

    SQL登録の parameters に以下を設定します。

    php
    'tenantId' => ['type' => 'int64'],
'name' => ['type' => 'text', 'nullable' => true],
'enabled' => ['type' => 'bool', 'nullable' => true],
    sql
    SELECT id, name FROM users
/*%where*/
WHERE tenant_id = /*:tenantId*/1
/*%if name != null*/
    AND name = /*:name*/'demo'
/*%end*/
/*%if enabled != null*/
    AND enabled = /*:enabled*/TRUE
/*%end*/
/*%end*/
ORDER BY id

    入力例は ['tenantId' => 10, 'name' => null, 'enabled' => true]。NULLの条件だけを省略します。テナント条件や更新対象IDは任意条件にしないでください。

    WHERE/HAVINGの本文には実際のキーワードを書きます。残った先頭のAND/ORを1個だけ取り除き、本文が空なら句全体を省略します。SETは先頭カンマを1個だけ除去し、空なら TW_EMPTY_SET。末尾のANDやカンマは自動修復しないため、区切りは各条件の先頭へ置きます。

    elseとサンプル実行

    sql
    SELECT id FROM users WHERE
/*%if active*/
    enabled = TRUE
/*%else*/
--| enabled = FALSE
/*%end*/

    active はboolとして宣言します。DBクライアントで直接実行する際は最初の枝だけが見えるよう、elseif/elseのSQL行は --| で隠します。制御命令だけの行にはマスクを付けません。

    式は == != < <= > >=、! && ||、括弧、isEmpty(path)、count(path) を利用できます。比較は型を区別し、ifの結果はbool必須です。PHP関数・メソッド呼び出し、暗黙の真偽値変換、連鎖比較はできません。未選択の枝もパラメータ宣言・必須キーの検査対象です。

    ループでVALUESを作る

    php
    'rows' => ['type' => 'list<record>', 'fields' => [
    'userId' => ['type' => 'int64'],
    'tag' => ['type' => 'text'],
]],
    sql
    INSERT INTO user_tags (user_id, tag) VALUES
/*%for row in rows separator=", " empty="error"*/
    (/*:row.userId*/1, /*:row.tag*/'demo')
/*%end*/
RETURNING user_id, tag

    このSQLは kind=write_returning で登録します。separatorは ", "、" AND "、" OR " のいずれかの固定値。emptyは error（既定）か omit。omitを使う場合は空でも周囲のSQLが成立する構造にします。

    loop.index は0始まり、loop.first / loop.last はboolです。元の入力位置を表します。入れ子では最も内側のloopを参照します。外側変数と同じ名前は使えません。

    安全なソート

    sort をtextパラメータとして宣言し、入力で選べるキーをSQL登録の sorts に定義します。

    php
    'parameters' => ['sort' => ['type' => 'text']],
'sorts' => ['sort' => [
    'name_asc' => [
        ['column' => ['u', 'name'], 'direction' => 'ASC', 'nulls' => 'LAST'],
        ['column' => ['u', 'id'], 'direction' => 'ASC'],
    ],
]],
    sql
    SELECT u.id, u.name FROM users u
ORDER BY
/*%orderBy sort*/
    u.name ASC NULLS LAST, u.id ASC
/*%end*/

    入力は ['sort' => 'name_asc']。ORDER BYはブロックの直前に書き、内部には項目だけを置きます。この命令はORDER BYキーワードを自動追加しません。未登録キーは TW_SORT になり、入力から列名やSQL断片を組み立てることはありません。一意なidを最後に入れると順序が安定します。

    列選択と部分更新

    列選択はtext入力を projections の登録キーへ対応させます。

    php
    'parameters' => ['projection' => ['type' => 'text']],
'projections' => ['projection' => [
    'summary' => [
        ['column' => ['u', 'id']],
        ['column' => ['u', 'name'], 'alias' => 'display_name'],
    ],
]],
    sql
    SELECT
/*%columns projection*/
    u.id, u.name AS display_name
/*%end*/
FROM users u

    列は宣言順に出力され、各識別子を引用します。式・関数・ワイルドカードの展開はできません。1つの選択は最大1000列です。

    部分更新の入力は patch<record>。省略したフィールドは変更せず、明示NULLはnullable列をNULLへ更新します。

    php
    'parameters' => [
    'patch' => ['type' => 'patch<record>', 'fields' => [
        'name' => ['type' => 'text', 'nullable' => true, 'column' => 'name'],
        'active' => ['type' => 'bool', 'column' => 'active'],
    ]],
    'id' => ['type' => 'int64'],
    'tenant' => ['type' => 'int64'],
],
    sql
    UPDATE users SET
/*%assignments patch*/
    name = 'demo', active = TRUE
/*%end*/
WHERE id = /*:id*/1 AND tenant_id = /*:tenant*/1

    入力 ['patch'=>['name'=>null], 'id'=>1, 'tenant'=>10] はnameだけを変更します。空patchはエラー。id、tenant_id、lock_version、created_at、created_on、created_byはfield名またはcolumn名が該当すると既定で保護されます。フィールドごとに protected で明示設定できます。WHERE条件やバージョン増分は自動追加しません。

    Domaサブセットの移行

    クエリごとに grammar => 'doma-subset-v1' を指定すると、限定した /* path */sample のバインドや条件文を移植できます。自動判定はしません。トップレベルのgrammarは canonical-v1 のままにします。

    canonicalの /*:path*/ との混在や、任意の式展開・関数呼び出し、Doma全機能の互換は対象外です。NULL・空IN・必須キーは本パッケージの契約に従うため、元のテンプレートと同じ結果になることをケースで検証してください。

    機能 doma-subset-v1での扱い
    scalar/listバインド、if/end 対応。宣言済みpathと限定したbool式を使用
    elseif/else/for 非対応、TW_COMPATIBILITY
    where/set/orderBy/columns/assignments canonical専用。移植用モードでは使用不可
    count/isEmpty、@関数、メソッド呼び出し 非対応
    WHERE等の空句削除、先頭AND/ORの補正 非対応。条件前に固定predicateが必要
    SQL埋め込み、literal変換、--|マスク 非対応
