    検証・デプロイ・運用

    キャッシュ、接続の選択、合成ケース、診断とログの運用。

    デプロイとASTキャッシュ

    SQL・config・生成PHP・manifestを同じ版で配布します。キャッシュはSQLソースを置き換えるものではありません。

    bash
    php artisan twoway:lint
php artisan twoway:generate --check
# 雛形も生成している場合は、各対象を明示して --check する
php artisan config:cache
php artisan twoway:clear
php artisan twoway:cache

    DAO/manifestを利用しているアプリの例です。生成物を使わないアプリではgenerateの手順は不要です。生成物の差分は開発・ビルド環境でwriteしてレビューし、デプロイ時にはcheckで鮮度を確認します。

    SQLの内容hashで変更を検出するためmtimeだけには依存しません。SQL・設定・生成契約を変更したら、長寿命queue worker / Octane workerも再起動してください。AST cacheの書込み先と生成物は信頼済みユーザーだけが変更できるように管理します。

    read/writeと接続の選択

    通常のreadはLaravelのreader、transaction中やsticky成立時はwriterを使用します。write / RETURNING / lockingはwriterです。未使用のwriterへ接続してreadを止めることはせず、実際に選択したPDOの設定を検証します。

    タイムアウト指定、plan advice、each/eachAsにはLaravel管理のtransaction scopeが必要です。別reader PDOに分離される構成では TW_UNSUPPORTED になるため、replica endpointを専用のnamed connectionへ登録します。ambient transactionやstickyでwriterが選ばれる場合は使用できます。

    診断の有効化とリセット

    php
    'diagnostics' => [
    'coverage' => true,
    'execution' => true,
    'max_sources' => 128,
    'max_arms' => 100000,
    'max_events' => 256,
],
    php
    use Hft\TwoWaySql\Compiler\Trace\CoverageCollector;
use Hft\TwoWaySql\Laravel\Diagnostics\ExecutionTrace;

$coverage = app(CoverageCollector::class);
$trace = app(ExecutionTrace::class);
$branchReport = $coverage->snapshot();
$events = $trace->snapshot();

// アプリのrequest/job境界に合わせて実施
$coverage->clear();
$trace->clear();

    coverageはSQL ID/source hashごとに分岐・loopの通過を記録します。source変更後の集計は混ぜません。上限による truncated / evictedSources がある場合は部分的な集計です。

    ExecutionTraceはSQL ID/hash、elapsedMicroseconds、行数、errorCode/SQLSTATE、通過分岐ID等を保持します。SQL本文・実入力・結果セルは保持しません。実行の診断であり、後段のoneの厳密件数検証や通常DTO変換の成功とは区別してください。

    合成ケースを作る

    入門のdemo.value に対応する tests/sql/cases.json の例です。

    json
    {
  "schema_version": "1.0",
  "cases": [{
    "id": "value_seven",
    "query_id": "demo.value",
    "parameters": {"value": 7},
    "expected_pdo_sql": "SELECT ?::bigint AS value;",
    "expected_bindings": [7],
    "comparison": "tokens",
    "expected_rows": [{"value": 7}]
  }]
}
    bash
    php artisan twoway:check tests/sql/cases.json --json
php artisan twoway:coverage tests/sql/cases.json --json

    ここまではDBへ接続せず、expected_rowsは検査しません。comparisonはbytesまたはtokens。列値・型は厳密比較し、row_order=unorderedで行順だけを無視できます。期待エラーはexpected_errorとerror_phase=compile/executeを指定し、成功期待と混在させません。

    v2ではschema_versionを2.0にし、prepare（登録write）とassertions（登録read）を追加できます。各リストは20stepまで、準備の期待件数合計10000、assertionは1000行まで。対象writeのexpect_rowsで期待更新件数も指定できます。各ケースは準備→対象→事後照合を同じtransactionで行い、最後にrollbackします。v1のケースへv2専用フィールドを追加してはいけません。

    隔離DBでの検証

    check/coverageのexecute、inspect、explainには、通常アプリと別の使い捨てDBを使います。次を事前準備します。

    1. Laravelへ専用pgsql接続を登録する。read/write分離、URL、接続先overrideは指定しない。
    2. DB名はunderscore区切りでtestまたはtestingを含み、prod/production/liveを含めない。
    3. testing.connection、allowed_hosts、allowed_databasesを完全一致で登録する。
    4. 環境ごとに32〜128桁の小文字hex nonceを生成し、環境設定とDB markerへ同じ値を設定する。
    php
    'testing' => [
    'connection' => 'twoway_test',
    'allowed_hosts' => ['127.0.0.1'],
    'allowed_databases' => ['twoway_sql_test'],
    'nonce' => env('TWOWAY_TEST_NONCE'),
],

    DB準備処理で public._twoway_case_marker の nonce 列に唯一の行を置きます。CLIはmarkerを自動作成しません。nonceは例えば bin2hex(random_bytes(16)) で生成し、Gitに保存しません。接続先の実DB名・nonceを照合してからSQLを送信します。

    bash
    php artisan twoway:check tests/sql/cases.json --execute --connection=twoway_test --json

    外側transactionやpretend状態では実行できません。APP_ENVだけでは許可されません。成功・失敗ともrollbackしますが、sequence増加や外部関数の副作用までは戻せないので、実データを使わないでください。

    ログとアプリ側の責務

    SQL・manifestを信頼済みコードとして管理し、入力をSQL断片へ連結しないでください。認可・テナント条件・SoftDeletes・更新ID・version条件・結果件数制限はSQLに記述します。

    パッケージの例外やtraceと、LaravelのQueryExecuted listener / query log / Telescope / APM / DBサーバーログは別経路です。ホスト側でもbindやDB例外本文を記録しないよう設定します。CompiledQuery::bindings()、JsonDocument::raw()等の明示取得値をログへ渡さないでください。

    接続断と再試行

    パッケージは書き込みを自動再送しません。commit応答が失われた場合の成否やexactly-onceを保証しないため、業務側の冪等キー・状態照合手順で扱います。SQLSTATE 57014はquery canceled、55P03はlock unavailableで、timeoutだけを一意に表すものではありません。
