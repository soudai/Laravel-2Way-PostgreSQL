    取得・更新と実行API

    厳密な取得件数、DTO、トランザクション、バッチ、ページング、逐次取得。

    Facade・Manager・接続

    Hft\TwoWaySql\Laravel\Facades\TwoWaySql とDI可能な Hft\TwoWaySql\Laravel\TwoWaySqlManager は同じ操作を提供します。connection(?string $name = null) は新しいExecutorを返し、共有サービスの接続設定を変更しません。nullはLaravel既定接続です。

    以下の表では、id は登録SQL ID、parameters は連想配列または SqlParameters、class は結果DTOのクラス名です。

    取得・更新API一覧

    呼び出し kind 返却値・契約
    compile(id, parameters) 各kind CompiledQuery。DB接続なし
    select(id, parameters) read / locking list<stdClass>。0件は空配列
    one(id, parameters) read / locking stdClass。厳密1行
    oneOrNull(id, parameters) read / locking 0行はnull、1行はstdClass
    scalar(id, parameters) read / locking 厳密1行1列。セルのNULLは許可
    execute(id, parameters) write int。実更新件数
    returning(id, parameters) write_returning list<stdClass>。0件は空配列
    selectAs(class, id, parameters) read / locking list<DTO>
    oneAs(class, id, parameters) read / locking DTO。厳密1行
    oneOrNullAs(class, id, parameters) read / locking 0行はnull、1行はDTO
    returningAs(class, id, parameters) write_returning list<DTO>。変換失敗時は当該更新をrollback
    executeExpecting(id, parameters, expected) write int。期待件数が違えば当該操作をrollback
    batch(id, parameterSets, options) write BatchResult
    paginate(query, parameters, page) data/countともread PageResult
    each(id, parameters, consume, fetchSize=1000) read callbackへ渡した行数
    eachAs(class, id, parameters, consume, fetchSize=1000) read DTOをcallbackへ渡した行数
    withOptions(options) — 実行オプションを持つ新しいExecutor

    kindの不一致は実行前に TW_QUERY_KIND。厳密件数の違反は TW_CARDINALITY。one系は取得後に件数を検証し、SQLへLIMITを追加しません。

    CompiledQueryを調べる

    sql() がPDO向けSQL、bindings() が実行用の値配列です。公開プロパティには sqlId、kind、hash、diagnostics、minimumPostgres があります。bindingsには実値が入るので、本番のログへ出さないでください。

    更新とRETURNING

    次の例は users.rename をwrite_returning、idをint64、nameをtextで登録します。

    sql
    UPDATE users SET name = /*:name*/'demo'
WHERE id = /*:id*/1
RETURNING id, name
    php
    use Hft\TwoWaySql\Laravel\Facades\TwoWaySql;

$rows = TwoWaySql::connection('pgsql')->returning(
    'users.rename', ['id' => 1, 'name' => 'Alice'],
);

    RETURNINGのないDMLは kind=write で登録してexecuteを呼びます。書き込みはwriter接続を使い、既存transactionに参加します。transactionがなければattempts=1で開始します。RETURNINGが0行でも、Laravelの変更済み・sticky状態は保守的に維持します。

    トランザクションと期待件数

    php
    use Illuminate\Support\Facades\DB;
use Hft\TwoWaySql\Laravel\Facades\TwoWaySql;

DB::connection('pgsql')->transaction(function (): void {
    $queries = TwoWaySql::connection('pgsql');
    $queries->executeExpecting('users.update', [
        'id' => 1, 'tenantId' => 10, 'version' => 0, 'name' => 'Alice',
    ], 1);
});

    users.update はwriteとして登録し、全入力を宣言した次のSQLを使用します。

    sql
    UPDATE users SET name = /*:name*/'demo', lock_version = lock_version + 1
WHERE id = /*:id*/1 AND tenant_id = /*:tenantId*/1
  AND lock_version = /*:version*/0

    executeExpectingは0以上の期待件数を受け付け、違反時に TW_AFFECTED_ROWS を返します。外側transactionがある場合もsavepointを使うため、呼び出し側で例外をcatchしても当該変更は残りません。0件はID不存在やテナント不一致でも発生し、楽観ロック競合とは断定できません。

    通常のexecuteが既存transaction内でDBエラーになった場合、そのtransactionを自動復旧する契約ではありません。復旧境界が必要な処理にはexecuteExpectingや 実行scope を使います。locking queryは同じ接続の既存transactionが必須です。

    結果DTO

    php
    <?php
namespace App\Data;

final readonly class UserRow
{
    public function __construct(public int $id, public string $name) {}
}
    php
    $rows = TwoWaySql::selectAs(\App\Data\UserRow::class, 'users.search', $parameters);

    列aliasとpublic constructor引数を対応させます。欠落・余剰列、重複alias、NULL不許可、変換不能は TW_MAPPING。constructorの既定値で欠落列を補いません。int/string/bool、BackedEnum、DateTimeImmutable、range型、明示converter等を使えます。Eloquent Modelのhydrateは行いません。

    列名が違う場合は Mapping\ColumnMap を Mapping\DtoMapper に登録します。snake_caseの自動変換は既定で無効です。floatや独自型は明示converterを検討してください。returningAsはDTO変換までtransaction/savepointに含め、変換失敗時にその更新を戻します。

    バッチ

    php
    use Hft\TwoWaySql\Laravel\Batch\BatchOptions;

$result = TwoWaySql::batch('users.update', $parameterSets,
    new BatchOptions(atomic: true, maxItems: 1000, expectedRowsPerItem: 1),
);

    parameterSetsはiterableで、各要素が通常の入力スキーマに従います。affectedRows は各要素の更新件数の配列、completedIndexes は0始まりの処理済み位置、committed は実commit済みかを表します。合計は array_sum($result->affectedRows) で取得できます。外側transaction内なら成功してもcommitted=falseです。

    atomicの既定はtrue。falseは外側transactionがない場合だけ許可され、成功済みの要素を個別commitします。失敗時は停止し、BatchException の failedIndex、completedIndexes、causeCode、sqlState を確認できます。空iterableはSQLを実行しません。接続断時の失敗要素のcommit成否は不明になり得ます。

    明示COUNTによるページング

    php
    use Hft\TwoWaySql\Laravel\Pagination\PageQuery;
use Hft\TwoWaySql\Laravel\Pagination\PageRequest;

$page = TwoWaySql::paginate(
    new PageQuery('users.page', 'users.count'),
    ['tenantId' => 10],
    new PageRequest(page: 2, perPage: 20, maxPerPage: 100),
);

    data SQLには _pageLimit と _pageOffset を必須int64として宣言し、LIMIT/OFFSETへbindします。count SQLには検索条件だけを宣言します。入力から予約名を渡してはいけません。

    sql
    SELECT id, name FROM users WHERE tenant_id = /*:tenantId*/1
ORDER BY id LIMIT /*:_pageLimit*/20 OFFSET /*:_pageOffset*/0
    sql
    SELECT count(*) FROM users WHERE tenant_id = /*:tenantId*/1

    COUNT→dataの順に同じ接続で実行します。返却は rows / total / page / perPage / totalPages。total=0ならtotalPages=0です。COUNTは厳密1行1列・非負整数。SQLの書換えでCOUNTを自動生成しません。両クエリのsnapshot一致が必要なら、アプリ側で同じ接続のREPEATABLE READ transactionを明示します。

    カーソルによる逐次取得

    php
    $count = TwoWaySql::connection('reporting')->each(
    'users.export', ['tenantId' => 10],
    static function (\stdClass $row): bool {
        // 1行ごとの処理。falseを返すとこの行までで停止。
        return true;
    },
    fetchSize: 128,
);

    read専用。fetchSizeは1〜10000、既定1000です。PostgreSQLカーソルから分割取得し、全件取得・早期終了・例外のいずれでもcursorを閉じます。eachAsは同様にDTOを渡します。callback内で接続を切断したり、transactionをcommit/rollbackしないでください。

    分離reader PDOでは使用できないため、replicaへは専用のnamed connectionを作ります。メモリ上限はfetchSizeと行サイズに依存し、callbackでの全件保存や無制限なquery logまでは制限しません。外部出力はDB rollbackでは元に戻りません。
